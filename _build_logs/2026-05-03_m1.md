### Plan corrections (apply during Layer 1):

1. **`struct Inhibitor.elapsed` (NOT `created`)** — OpenAPI spec at `logs/core-openapi.yaml:16734` says `created` but the running firmware returns `elapsed`. Spec-vs-implementation drift. Trust the wire.
2. **DELETE response handling** — code 200 with `{"code":"OK","message":"..."}` body. The signal `respDeleteInhibitor(reqId, httpCode, errorMessage)` shape stays right; `errorMessage` will be empty on success.
3. **Orphan filter must be `who == "madalone.session-keeper"`** specifically — relying on `PowerModeResponse.standby_inhibitors==true` to detect orphans would over-match (other clients' inhibitors trigger it).
4. **Server generates UUID4 ids when not supplied** — we won't supply ids; just store what comes back.
5. **Bearer auth path NOT tested in this capture** — only Basic. Phase 0 probe (commit `f500bf4`) confirmed Bearer works internally; the body shape is identical regardless of auth header. The first-runtime `qCWarning` log (§1.12 step 4) will catch any Bearer-specific surprises in production.

## Decisions Made

- **REST helpers as parallel infrastructure to the probe** — `m_restNam` separate from `m_probeNam`. Probe stays as one-shot diagnostic; M1's REST is the production code path. Both reuse factored helpers (`readUcToken`, `restEndpoint`, `bearerHeader`).
- **Hard-fail on REST auth flake** (audit recommendation). No silent fallback to WS ping path. The user notices and either retries or flips toggle off.
- **Orphan cleanup recreates fresh** (option (b) in plan, not (a) adoption). Adopting an unknown ID has subtle correctness concerns; recreating is unambiguous, and the inhibitor is fast/cheap.
- **Mid-session toggle flip is supported** in both directions. Defensive — toggle is generally OFF in practice; this is the rare-but-correct path.
- **`onCoreDisconnected` doesn't try to delete the inhibitor** — the WS is down, the call would fail. The reconnect orphan-cleanup handles it.
